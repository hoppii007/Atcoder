## 問題

H×W のグリッドに HW 枚のカードがあり、i=1,…,N について カード i は (A_i, B_i) にある。残りは空白。
次の操作を可能な限り繰り返す:

1. 数の書かれたカードが1枚も無い行があれば、その行を取り除き上に詰める。
2. 数の書かれたカードが1枚も無い列があれば、その列を取り除き左に詰める。

各カード i の最終的な位置 (C_i, D_i) を求める。最終配置は操作順によらず一意。

入力:
```
H W N
A_1 B_1
⋮
A_N B_N
```
出力: N 行。i 行目にカード i の最終位置 C_i D_i。

**制約**

- 1 ≤ H, W ≤ 10^9
- 1 ≤ N ≤ min(10^5, HW)
- 1 ≤ A_i ≤ H
- 1 ≤ B_i ≤ W
- (A_i, B_i) は相異なる
- 入力はすべて整数

**考察ノート**

グリッド系で行ごとや列ごとの操作なので、行ごと列ごとに分割して考えると良さそう。
「操作の仕方によらず一意」とかいてあるので、やっぱり行ごと列ごとそれぞれ独立に操作すれば良くて、
座標圧縮して圧縮前 → 圧縮後の座標がわかれば良さそう。

**難所**

特になし

**レビュー(LLM)**

1. **考察ノートの評価** — 十分。この問題の核である「行と列は独立に処理できる」「空行/空列を詰める＝
   数のある座標だけを大小関係を保って詰め直す＝座標圧縮」という二段の言い換えを、どちらも自分の言葉で
   捉えられている。加えると良い一点は、**なぜ座標圧縮に落ちると確信したかの根拠を制約に結びつける**こと。
   H,W ≤ 10^9 でグリッドは実体化できないが N ≤ 10^5 なので「実際に効くのはカードのある行/列だけ」
   ——この制約差が座標圧縮を選ぶ決め手、と一言残すと後の横断分析で効く。

2. **弱点・思考の癖の指摘** — 初回ノートのため比較対象なし。詰まり無し（[]）で滞りなく解けており、
   本問については指摘なし。今後 座標圧縮／言い換え 系のノートが増えたら、この「大きい座標空間 →
   出現値だけに圧縮」という判断が安定して出せているかを追う。

3. **別解・より良い方針** — 方針は想定解そのもの。実装面の別解として、map の代わりに
   「ソート済みユニーク配列＋lower_bound」で圧縮すると O(log N) 参照が定数倍軽くなる。ただし本問の
   規模では現状で十分。

4. **実装の正しさ・計算量** — 正しい。行 hs・列 ws をそれぞれ独立に coordinate_compression にかけ、
   各カードの圧縮後座標 +1（1-indexed 化）を出力しており、題意通り。計算量 O(N log N)。
   気になる点は **出力の endl**：N 回すべてで flush が走る（N ≤ 10^5 なので今回は間に合うが、
   出力の多い問題では TLE 要因になる習慣）。"\n" にするか改行を貯めて最後に一括出力すると安全。
   これは正誤ではなく定数倍の注意。

## 問題全体のメモ

座標圧縮の典型。「巨大な座標空間だが出現する値は N 個だけ」→「大小関係だけ保って 0..K-1 に詰め直す」
という判断がそのまま解法。行・列が独立に処理できる点も本問の骨格。
