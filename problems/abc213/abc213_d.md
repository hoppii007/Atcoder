## 問題

AtCoder 国には 1〜N の番号がついた N 個の都市と N-1 個の道路があり、全都市は道路で互いに行き来できる（＝木）。
高橋くんは都市 1 を出発し、次のルールで旅をする:

- 現在いる都市に隣接する **未訪問の都市があれば、その中で番号が最小の都市へ移動する**。
- 未訪問の隣接都市がなければ、直前にいた都市へ戻る（都市 1 にいて戻れなければ旅を終える）。

高橋くんが訪れる都市を、開始時・終了時の都市 1 も含めて訪問順に空白区切りで出力する。

入力:
```
N
A_1 B_1
⋮
A_{N-1} B_{N-1}
```
出力: 訪問した都市の番号を訪問順に空白区切りで 1 行に出力。

**制約**

- 2 ≤ N ≤ 2×10^5
- 1 ≤ A_i, B_i ≤ N
- 全都市は道路を使って互いに行き来できる（連結、辺 N-1 本 ⇒ 木）
- 入力はすべて整数

**考察ノート**

オイラーツアーを行きがけ順で答えてくれという問題。行き先のソートにならし O(N log N)、
探索に O(N) なので十分間に合う。

**難所**

難所というほどではないが、再帰部分の実装で 1 WA した。
「行き先がなければ戻ってきた自分を表示せずに戻る」みたいな処理をしたかったときに、
「nexts[i].size() == 1 なら return」としてしまったが、1 本線の木（パスグラフ）のときおかしくなる。
グラフや木上の再帰はたまにゴチャらせるので、しっかり詰めてから実装しても良いかも。

**レビュー(LLM)**

1. **考察ノートの評価** — 過不足なし。問題を「オイラーツアー（行きがけ・帰りがけ両方を記録する木の walk）」
   と一語で言い換え、計算量の内訳（隣接ソート O(N log N)＋探索 O(N)）まで押さえられている。この問題は
   考察の難所ではなく実装の詰めが本体なので、ノートとしてはこの粒度で十分。強いて足すなら、
   「番号最小の未訪問へ進む」＝**各隣接リストを昇順ソートしてから DFS すれば貪欲が自動で満たされる**、
   という「ルール → 実装への落とし方」を一言残すと、後で似た『順序指定つき探索』問題と繋がる。

2. **弱点・思考の癖の指摘** — 木DFS 系ノートの初回のため横断比較の相手はまだ無い。ただし今回の 1 WA は
   典型的な形をしている: **「次数・本数で base case を書いて特定の木形状（ここではパスグラフ）で崩れる」**。
   本来この walk は base case を明示せず「親以外の隣接を全部再帰し、無ければ自然に戻る」と書けば
   条件分岐が要らない（実際、最終 AC コードはそうなっている）。`size()==1` のような**構造の数え上げで
   終了条件を書きにいく癖**は、根 (parent=-1) や一直線の木で境界がずれやすい。今後 木DFS タグの回が
   増えたら、この「base case を条件式で作りにいく → エッジ形状で落ちる」が再発するか追う価値がある。
   （つまずき分類: 実装バグ）

3. **別解・より良い方針** — 方針は想定解そのもの。実装の別解として、深さ最大 2×10^5（パスグラフ）で
   **再帰が深くなる**ため、環境によってはスタック配慮が要る点だけ注意（AtCoder の既定スタックなら通常は
   問題ないが、明示的スタックでの反復 DFS にすれば安全）。また本問で必要なのは訪問列 `tour` だけで、
   `EulerTour` が持つ `in`/`out` は未使用——ライブラリとして汎用に持つのは妥当だが、この問題単体では
   `tour` の生成だけで足りる。

4. **実装の正しさ・計算量** — 正しい。`dfs` は `in[now]` を記録して `now+1` を push、親以外の各隣接へ
   再帰し**戻るたびに `now+1` を push**、最後に `out[now]` を記録する。これがまさに高橋くんの walk
   （子から戻るたびに現都市を再訪）に一致し、葉（隣接が親のみ）はループが空回りして自然に戻るので
   base case は不要。各隣接リストを昇順ソート済みなので「番号最小へ進む」も満たす。
   計算量は隣接ソート O(N log N)＋DFS O(N)、出力は `endl` 1 回で flush も 1 回。問題なし。

## 問題全体のメモ

木のオイラーツアー（行きがけ・帰りがけ両方を記録する walk）の素直な典型。
「番号最小の未訪問へ進む」は各隣接リストを昇順ソートしてから DFS する、で自動的に満たせる。
walk を素直に書けば base case は不要（親以外を再帰し尽くせば自然に戻る）で、
次数で終了条件を作ると path 型で崩れる——という実装上の教訓が本問の実質。
自作ライブラリ: [EulerTour](../../honban/main.cpp)（tour と in/out を生成する struct）。
