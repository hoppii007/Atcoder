## 問題

N 匹のすぬけくんが反時計回りに 1..N と円環状に並んでいる。すぬけ i が時刻 t に宝石を
受け取ると、その S_i 秒後（時刻 t+S_i）にすぬけ i+1 へ宝石を手渡す（すぬけ N+1 = すぬけ 1）。
高橋くんはすぬけ i に対し、時刻 T_i に宝石を1つ渡す。複数の宝石が同時に巡回してよく、
1匹が同時に複数受け取ることもある。各すぬけ i が **最初に宝石を受け取る時刻** を求める。

入力:
```
N
S_1 S_2 ... S_N
T_1 T_2 ... T_N
```
出力: N 行。i 行目にすぬけ i が最初に宝石を受け取る時刻。

**制約**

- 1 ≤ N ≤ 2×10^5
- 1 ≤ S_i, T_i ≤ 10^9
- 入力はすべて整数

**考察ノート**

グラフっぽい見た目をしているのでグラフにしたい。
時刻管理より辺にコストをつけて最短経路とかにしたいので、
高橋くんが始めて宝石を誰かに手渡す時刻 S を 0 として、そこから各人 i に宝石が渡る時間を求めれば良さそう。
グラフとしては高橋くんの頂点＋各すぬけくんの頂点で、すぬけくんの頂点は円環になっててコストは t のままで OK。
高橋くん → 各すぬけくんのコストは、渡す時刻 − S で良さそう。

**レビュー(LLM)**

① 考察ノートの評価
「時刻を追うのではなく、宝石の受け渡しを辺コストに落として最短経路に帰着する」という核心を
きちんと言語化できている（＝タグ グラフ帰着 の典型的な着眼）。良い。
ただし補うべき点が2つ:
- **ツール選択の根拠が無い**：辺コスト（S_i, T_i ≤ 10^9）は 0/1 でないのに `bfs01`（01BFS）を
  使っている。なぜ Dijkstra ではなく bfs01 で正しく／速くなると判断したのかが残っていない。
- **`mi` 減算の意図が未記録**：実装の `mi = min(t)` を引いて最後に足す操作が考察に無く、
  後から読むと目的不明。実際これは「始点辺を一律 mi だけ下げて最後に戻す」＝**正当性中立の無効操作**
  （全経路がちょうど1本の始点辺を通るため全距離が一律 mi 下がり、出力で戻る）。最小始点辺を 0 に
  するだけで、辺コストを 0/1 構造にはできていない。書き残すか、不要なら消すのが良い。

② 弱点・思考の癖
自力AC・簡単・詰まり無しで、考察自体に弱点は見えない。唯一の癖候補は上記の
**「bfs01 を 0/1 辺でない問題に流用している」**点。今回は下記④の通り結果的に正しく動くが、
01BFS の適用条件（全辺 ∈ {0,1}）の理解にズレがある可能性。新規ノートのため過去記録との突合は次回以降。

③ 別解・より良い方針
グラフを構築せずとも **環を2周する O(N) の1行DP** で解ける。
answer[i] = min(T_i, answer[i-1] + S_{i-1}) を、円環上で2周（i を 0..N-1 で2回）舐めるだけ。
最短経路は高々1周しか回らない（1周すると ΣS>0 が乗り悪化する）ので2周で収束する。
グラフ・deque 不要、O(N) 時間・O(N) 空間で最もシンプル。

④ 実装の正しさ・計算量
- **正しさ：正しい**。この `bfs01` は visited を持たず、`bfs01s[next] <= ncost` の比較で
  改善時のみ更新・再push する **label-correcting（SPFA 相当）**として書かれている。辺コスト ≥ 0 で
  改善のたびに再伝播するため、真の最短距離に収束する。純粋な 01BFS ではない。
- **計算量：注意**。deque の push_front/push_back（cost==0 か否か）は、辺が 0/1 でない本問では
  処理順を保証しない。つまり bfs01 本来の売りである O(V+E) は成立せず、理論上は SPFA 相当（最悪 O(VE)）。
  本問のグラフは「単一の有向サイクル＋全頂点への始点辺」という素直な構造で、実際には各頂点の
  再緩和が少なくほぼ O(N) で通る（N ≤ 2×10^5 でも AC）が、**ワーストの理論保証は無い**点は認識しておきたい。
  正攻法で保証したいなら Dijkstra（O((V+E)log V)）か、③の O(N) 2周DP。

## 問題全体のメモ

グラフ帰着の典型。実装は `honban` の bfs01（label-correcting 版）でも通るが、
本問の最短経路は「環を高々1周」なので **環2周の O(N) DP** が最短・最軽量。
