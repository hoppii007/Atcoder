## 問題

10^9 個の箱と N 個のボールがあり、いずれも 1 から番号付けされている。各箱にはボールを高々 1 個入れられる。
ボール i は「L_i 以上 R_i 以下の番号の箱」に入れなければならない。すべてのボールを条件を満たすように
箱へ入れられるか判定する。T ケースを処理する。

- 入力: `T` に続けて各ケース `N` の後 `L_i R_i` を N 行。
- 出力: 各ケースについて入れられるなら `Yes`、不可能なら `No`。

**制約**

- 1 ≤ T ≤ 2 × 10^5
- 1 ≤ N ≤ 2 × 10^5
- 1 ≤ L_i ≤ R_i ≤ 10^9
- 全ケースの N の総和 ≤ 2 × 10^5

**考察ノート**

とりあえず、自分だけが入れられる箱がある人は、そこに入れていい。その箱に入れられる人が複数ある時、
どんな順番に入れていけばいいか？を考えると良さそう。貪欲かなぁ。区間スケジューリング的に、
終わりが早い人を選択するといいのかも。終わりが遅い人はまだ入れられる可能性があり、終わりが早い人は
チャンスが少ないということなので。一つ以上被っている区間に対して、一番左から入れるボールを決定していけば
良さそう？決定の回数は N 回なので、次を選ぶ処理を O(1) でできれば計算量はよさそう。証明しとこうかな。
いやー、厳密には証明してませんが、「より可能性がある方を残す」貪欲なのでいいと思います。
その箱に入るボールが1つしかいない時にそれを選べばいいのはそれはそうで、複数あった場合、
最適解がこの貪欲の候補 D を選ばず、D' を選んだとします。最適解のその後に D が選ばれていない場合は、
ここで D を選んでも良く、選ばれている場合は先の D を今選んだことにして、後から D を入れていたところに
D' を入れられる（D' の方が終了が遅いので）。よって証明できてるのでこれで良さそう。

**レビュー(LLM)**

**① 考察ノートの評価** — 十分に良い。貪欲の方針（区間スケジューリング＝終端が早いものを優先）を自力で
引き当て、さらに **交換論法まで書き切っている** のが特に良い。「候補 D を貪欲が選ぶ／最適解が D' を選ぶ→
D の終了が早いので後で D' と入れ替えられる」という論法は本質を突いており正しい。
補うなら 1 点だけ：**なぜ箱を全探索せず O(N) 点しか見なくてよいか**（箱は 10^9 個あるが、
訪れる価値がある座標は「区間の開始点」と「1 個確定させた直後の +1」だけ、というイベント処理の視点）を
明示しておくと、`10^9` という制約が「座標全探索は不可能→イベントだけ処理」を要求している構造が
一行で追える。方針（貪欲）はよく言語化できているが、値域の広さへの対処の言語化がやや薄い。

**② 弱点・思考の癖** — 今回は詰まり無し（30 分・自力・証明付き）。方針を立てて交換論法で裏を取る流れが
自然にできており強み。貪欲・イベントソート系タグの初出のため過去比較の材料はまだ無い。今後
「終端が早い順に取る」型が増えたら、本問を基準点に横断整理できる。

**③ 別解・より良い方針** — 想定解と本質同一。公式解説は `multiset` の代わりに **min-heap（R を優先度）** を
使うが、「開始点でボールを投入し、位置を進めながら R 最小を取り出す」という骨格は完全に一致する。
乗り換える必要はない。強いて言えばデータ構造を `priority_queue<pll,greater>`（R を first に）にすると
`set_comp` を書かずに済み実装が数行短くなる程度。

**④ 実装の正しさ・計算量** — 正しい。
- 貪欲の核：`now`（R 昇順 multiset）から `begin()`（R 最小）を取り出して now_p に置く。
  実行不能なボール（R < now_p）は `ans++` せず捨てるので、最終的に `ans < n` → `No` となり整合。
- **`ends` マップは完全な dead code**：`ends[r].pb(...)` で埋めているが一度も読んでいない。削除してよい
  （毎ケース map 構築のコストと可読性の無駄）。
- 軽微：`now_p++` 後の `starts[now_p]` は `map::operator[]` なので、存在しないキーに空 vector を挿入し
  map を膨らませる。`starts.count(now_p)` で分岐すれば無駄な挿入を避けられる（正しさには影響なし）。
- **定数倍（要注意）**：出力が `cout << "Yes" << endl;`。`endl` は毎回フラッシュするので T≤2×10^5 ケースで
  フラッシュが最大 2×10^5 回走る。`"\n"` に変え、`ios::sync_with_stdio(false); cin.tie(nullptr);` を
  入れておくのが安全（今回は通ったが T が上限に寄ると危うい）。→ つまずき分類には残さないが、
  今後 T が大きい問題で `endl` を使うと落ちうる点は注意（統制語彙「定数倍高速化」に該当する典型）。
- 計算量：全体 O(ΣN log N)。位置の +1 前進は 1 回の配置につき 1 回で、配置回数 ≤ N なので前進総回数も
  O(N) に収まる。N の総和 ≤ 2×10^5 で余裕。

## 問題全体のメモ

「各ボールに区間 [L,R]、箱は相異なる」→ **終端 R が早いボールを優先して置く貪欲**（区間スケジューリング）。
箱が 10^9 個あるので全座標は見ず、**開始点＋確定直後の +1 だけを訪れるイベント処理**で O(N) に落とす。
R 最小の取り出しは multiset か min-heap。実行不能ボールは置かず、置けた数が N 未満なら No。
交換論法：終端が早い候補を残すと後で終端が遅い候補と入れ替え可能なので最適性が保たれる。
