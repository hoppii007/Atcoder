## 問題

整数 N が与えられる。次を全て満たす最小の整数 X を求める。

- X は N 以上である。
- 非負整数の組 (a, b) であって X = a³ + a²b + ab² + b³ を満たすものが存在する。

**入力**：N（1 行）
**出力**：条件を満たす最小の整数 X

**制約**

- N は整数
- 0 ≤ N ≤ 10^18

### 第1回 — 2026-07-17

**考察ノート**

とりあえず因数分解してみる。(a+b)(a²+b²) となった。N 以上であって X=(a+b)(a²+b²) となる最小の X を求めたい。
片方固定すると良いとかだと有難いけど、O(√N) とかになって間に合わない、、、と思ったけど、片方を固定すると3乗根のオーダーで増えていくな。
結局 N の三乗根を A として O(A²) になるので間に合わないか。が、少なくとも a か b のどちらかは A 以下であることは間違いない。
あー、片方固定するともう片方は二分探索で行けるか。N 以上かどうかで単調性があるからいけそう。

**難所**

オーバーフローでずっと1件落ちていて、python に書き直して出したら通りました…

**レビュー(LLM)**

**① 考察ノートの評価** — 十分。因数分解 (a+b)(a²+b²) → 「片方固定で他方は三乗根オーダー」→「少なくとも一方は N^{1/3} 以下」→「他方は N 以上かどうかで単調なので二分探索」という、この問題の想定解の骨格を自分の言葉で一直線に辿れている。特に「a か b のどちらかは A 以下」という上界の議論を言語化できているのが良い。あえて補うなら、鍵制約 N≤10^18 → N^{1/3}≈10^6 という具体的な数値見積もりを明記しておくと、なぜ片側全探索が O(10^6) で間に合うかの根拠が残る。

**② 弱点・思考の癖** — つまずきは方針でなく実装（オーバーフロー）に集中。方針は詰まりなく正解に到達しており、時間を溶かしたのは「ll の積で 4 項合計が 9.2×10^18 を超えうる」値域評価の抜けと、その 1WA のデバッグ。この問題は本ノートベース初出だが、「a,b が最大 10^6 → 積 a³ 等が 10^18 級 → 合計 4×10^18」という値域の初手見積もりを立てる習慣があれば回避できた種類の詰まり。今後 N≤10^18 級の問題では「計算途中の最大値が符号付き 64bit に収まるか」を実装前に一度見積もる、を定型化したい。

**③ 別解・より良い方針** — 方針自体が想定解（小さい側を全探索＋他方を二分探索）なので変更点はなし。改善はオーバーフロー処理の簡潔化に尽きる。判定・値計算を `__int128` で行えば、本コードの lte/lt/gte/gt という 4 つの除算ベース比較関数が丸ごと不要になり、`(a+b)(a²+b²) ≥ n` をそのまま書ける。Python 退避も不要になる。

**④ 実装の正しさ・計算量** — ロジックは正しい。計算量 O(A·log A) ≈ 10^6×20 ≈ 2×10^7 で問題なし。N=0（X=0）、N=1（a=0,b=1）などの境界も追って正しい。最終値は unsigned long long で計算しており tmp≤~4×10^18 で収まる。可読性・冗長性の指摘のみ：
- `lt` / `gte` / `gt` は定義のみで未使用（実使用は `lte` だけ）。削除してよい。
- 177 行 `ll t = n-i*i*i;` は未使用変数。
- `f(n)` の `rep(i,n)` は上限が n だが実際は i³≥n で即 return するため実質 O(N^{1/3})。上限表記が誤解を招くので `while` かコメントで意図を残すと良い。
- 168 行のマジックナンバー `18446744073709551615` は `ULLONG_MAX`（`<climits>`）で書ける。

## 問題全体のメモ

想定解＝「片側全探索＋二分探索」の典型。対称式 (a+b)(a²+b²) で WLOG a≤b とすれば a≤N^{1/3}≈10^6 に抑えられ、a を固定すると b について単調増加なので b は二分探索で確定できる。実装上の急所は方針でなく 64bit オーバーフロー。`__int128` を使えば比較補助関数なしで素直に書ける。
