## 問題

N 頂点 M 辺の単純無向グラフが与えられる。頂点 S から出発し、ちょうど K 回辺を移動して
頂点 T に到達する経路（歩道: 同じ頂点・辺を複数回通ってよい）のうち、経路中に
頂点 X が **偶数回**（0 回を含む）現れるものの数を 998244353 で割った余りを求める。

**入力**

```
N M K S T X
U_1 V_1
⋮
U_M V_M
```

**出力**

条件を満たす経路数を mod 998244353 で 1 行に出力。

**制約**

- 2 ≤ N ≤ 2000
- 1 ≤ M ≤ 2000
- 1 ≤ K ≤ 2000
- 1 ≤ S, T, X ≤ N
- X ≠ S かつ X ≠ T
- 1 ≤ U_i < V_i ≤ N
- 単純グラフ（多重辺なし）

**考察ノート**

簡単なケースを考えてみる。「S から K 回移動して T にたどり着くルートを数える」という問題なら
グラフ DP で行けそう？ `dp[i][j]` := 頂点 i から j 回移動で頂点 T に行くルートの本数、として
メモ化再帰でいけそう。X の偶奇条件を状態に足して
`dp[i][j][k]` := 頂点 i から j 回移動で頂点 T に、X を偶数 or 奇数（k=0/1）回通っていける
ルートの本数、としてメモ化再帰でよさそう。

**難所**

（自力 AC・特記事項なし。パリティ次元の追加も詰まらず判断できている。）

**レビュー(LLM)**

1. **考察ノートの評価** — 良い。「素直な経路数え上げなら `dp[頂点][残り移動数]` のグラフ DP」という
   本筋をまず立て、そこに X の偶奇条件を **状態を 1 次元足す** ことで取り込む、という状態設計の
   過程が言語化できている。数え上げ DP の王道の詰め方（まず条件を落とした素朴版 → 制約を状態に
   吸収）を踏めている点が特に良い。欲を言えば「なぜ偶奇（parity）だけ持てば十分か（=X の訪問回数の
   絶対値は不要、偶奇のみが答えの条件を決める）」を一言残すと、同型（偶奇 state DP）の横展開が効く。

2. **弱点・思考の癖の指摘** — 現時点で詰まりの記録なし。自力 AC・状態設計を滞りなく決められており、
   このタグ（グラフDP / 状態設計）での弱点は観測されない。初回データ点として「グラフDP＋パリティ
   state を自力で組めた」を記録する。

3. **別解・より良い方針** — 方針は想定解そのもの（`dp[step][vertex][parity]`）。実装はメモ化再帰だが、
   反復 DP（`dp[j][i][k]` を j=0..K で前へ配る／もらう）に書き換えると再帰オーバーヘッドと
   スタック深さ K=2000 を回避でき、定数倍・安全性の両面で有利。計算量は同じ O(K·(N+M))。

4. **実装の正しさ・計算量** — 正しい。パリティの数え方（`i==X` のとき遷移で反転）は、始点 S≠X・
   終点 T≠X が制約で保証されるため「departing 頂点で数える」方式でも全 X 出現を過不足なく数えられる
   （最終頂点 T は X でないので取りこぼしなし）。計算量は状態 N·K·2、各状態で deg(i) を走査するので
   総計 O(K·(N+M)) ≈ 1.6×10^7 で十分間に合う。メモリは `modll dp[2000][2001][2]` ≈ 約 61MB＋
   `is_set_dp` 約 8MB で AtCoder の制限内。
   - 軽微: main 冒頭の `rep(i,2000) rep(j,2001) rep(k,2)` の初期化ループはグローバル配列が
     ゼロ初期化・`is_set_dp` も false 初期化されるため冗長（無害）。
   - 軽微: `i` の上限は 2000 固定だが n ≤ 2000 なので配列外参照はなし。反復 DP に直すなら
     この初期化も不要になる。

## 問題全体のメモ

グラフ DP に「追加の 1 bit 状態（ここでは特定頂点の訪問回数のパリティ）」を足す典型。
`dp[残りステップ][頂点][偶奇]` の 3 次元。偶奇・色・使用済みフラグなど「答えの条件が絶対数でなく
状態で決まる」ときにパリティ／少数 state を持たせる発想は横展開が効く。
