## 問題

H 行 W 列のグリッドがあり、上から i 行目・左から j 列目のマスを (i, j) と表す。
マスのうち (a_1, b_1), …, (a_N, b_N) の N 個はちょうど「穴」が空いている。

正整数の組 (i, j, n) について、左上隅を (i, j)、右下隅を (i+n−1, j+n−1) とする正方形領域が
次の条件を満たすとき「穴のない正方形」と呼ぶ:

- i + n − 1 ≤ H、j + n − 1 ≤ W（グリッドに収まる）
- 0 ≤ k ≤ n−1、0 ≤ l ≤ n−1 を満たす全ての (k, l) について、マス (i+k, j+l) は穴ではない

グリッド内の穴のない正方形の個数を求めよ。

**入力**

```
H W N
a_1 b_1
⋮
a_N b_N
```

**出力**

穴のない正方形の個数を1行に出力する。

**制約**

- 1 ≤ H, W ≤ 3000
- 0 ≤ N ≤ min(H × W, 10^5)
- 1 ≤ a_i ≤ H
- 1 ≤ b_i ≤ W
- (a_i, b_i) は相異なる
- 入力はすべて整数

（例: H=W=3000, N=0 のとき答えは 9004500500 で 32bit に収まらない）

**問題の核**

- 左上 (i, j) を固定すると「一辺 n の正方形が穴なし」は n について単調（n で穴なしなら n−1 でも穴なし）。
  (i, j) を左上とする穴のない正方形の数 ＝ 穴なしで取れる最大の一辺 n_max(i, j)。答えは Σ n_max。
- n_max は二次元累積和＋二分探索で O(log) で出せる。あるいは右下から `dp[i][j] = min(dp[i+1][j], dp[i][j+1], dp[i+1][j+1]) + 1`（穴なら 0）の O(HW) DP で直接出る。

**難所**

  判定が誤っていた。サンプル 1（H=2, W=3, 穴 (2,3)）で答えが合わない。デバッグ用の単体テスト `rect_sum(s, 0, 2, 1, 3)` も同じ順で書いたため、

③ 別解・より良い方針
- **O(HW) の DP**: 右下から `dp[i][j] = g[i][j] ? 0 : min(dp[i+1][j], dp[i][j+1], dp[i+1][j+1]) + 1`（範囲外は 0）。
  dp[i][j] がそのまま n_max(i, j) で、答えは Σ dp。累積和も二分探索も要らず、引数順の誤りが入る余地も無い。
  「(i, j) を左上とする最大正方形は、右・下・右下を左上とする最大正方形の min + 1」が言えれば立つ（最大正方形 DP の典型）。
- 二分探索を残す場合も、`ng = 3500` の定数ではなく `ng = min(h - i, w - j) + 1` にすると範囲外判定がいらず、意図が読みやすい。

④ 実装の正しさ・計算量（最終コード）
- 正しさ: 問題なし。`g[i][j]==0` のマスだけ見て ok=1 から始める初期値も正しく、範囲外は judge で false。
  答えは最大 9004500500 で `ll` に入っている。
- 計算量: O(HW log 3500) ≈ 9×10^6 × 12 ≈ 1.1×10^8 回の rect_sum。vector<vector> のランダムアクセスだが制限内。
- 可読性: judge ラムダを (i, j) ループの内側で毎回作っている点は動作上問題ないが、`max_side(i, j)` のような関数にすると二分探索の対象が名前で読める。
