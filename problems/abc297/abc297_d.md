## 問題

正の整数 A, B が与えられる。A = B になるまで次の操作を繰り返す。

- A > B なら A を A − B に置き換える。
- A < B なら B を B − A に置き換える。

A = B になるまでに操作を何回行うかを求めよ。有限回の操作で A = B になることは保証される。

入力は `A B` の1行。答えを1つ出力する。

（例: `3 8` → `4`、`1234567890 1234567890` → `0`、`1597 987` → `15`。入力は 32bit 整数に収まらない場合がある。）

**制約**

- 1 ≤ A, B ≤ 10^18
- 入力はすべて整数

**問題の核**

同じ側からの連続減算は A を A mod B にする操作で、その回数は floor(A/B) 回（互除法の 1 ステップ）。ただし A が B で割り切れると A=B で止まるので A/B − 1 回。ステップ数は O(log max(A,B))。

**難所**

- `int main()` を `int min()` と誤記してコンパイルエラー 2 回（2 回目は無修正の再ビルド）。ロジック上の詰まりはなし。

**レビュー(LLM)**

1. **考察の評価** — 鍵（連続減算を除算でまとめる・log で終わる）は 50 秒時点のログに言語化されている。不足は「割り切れる場合は A/B−1 回で止まる」という終了条件の扱いで、ここは誤りやすい箇所なのに実装で無言処理されている。また「10^18 回の愚直減算は間に合わない」という制約側の決め手も一言あるとよい。
2. **弱点・思考の癖** — この回で考察上のつまずきは無い。記録から読める事実は検証の薄さ: input 実行はサンプル1 のみで、割り切れ分岐を通るのは A=B（サンプル2）と、サンプル1・3 内の最終ステップだけ。今回はサンプル1 の最終ステップ（2,1 → a%b==0）で分岐が通っているが、A=B 即終了のケースは未実行。コンパイルエラー（タイポ・ライブラリ変更由来）は abc228_d・abc227_d・abc274_e にも記録があり、今回の「エラー後に無修正で再ビルド」はエラーメッセージを読む前にビルドを押し直した形跡。
3. **別解・より良い方針** — 割り切れ分岐を持たない書き方として、`while (b) { ans += a / b; a %= b; swap(a, b); }` で回数を数え、最後に 1 を引く（最後のステップは A=B で止まるため 1 回余分に数えている）方法がある。`gcd` を回す標準形と同じ形になり、分岐が減る。現行コードでも正しさ・計算量は同じ。
4. **実装の正しさ・計算量** — 問題なし。`a != b` のループで `b > a` なら swap、割り切れれば a/b−1 回足して a=b で終了、そうでなければ a/b 回足して a %= b（a%b>0 なので 0 にならず次ループで swap）。A=B なら 0。全変数 ll で 10^18 に対応、ans ≤ 10^18 で溢れなし。O(log max(A,B))。
   - 推移で直した誤り: `int min()` → `int main()`（コンパイルエラー 2 回）。
