## 問題

長さ N の正整数列 a=(a_1,…,a_N) が与えられる。次の 2 種類の操作を好きな順で何回でも行える。

- a_i が 2 の倍数である i を選び、a_i を a_i/2 に置き換える。
- a_i が 3 の倍数である i を選び、a_i を a_i/3 に置き換える。

すべての要素を等しく（a_1=a_2=…=a_N）するために必要な操作回数の最小値を出力する。不可能なら -1 を出力する。

（入力）
```
N
a_1 a_2 … a_N
```
（出力）最小操作回数、または不可能なら -1。

**制約**

- 2 ≤ N ≤ 1000
- 1 ≤ a_i ≤ 10^9
- 入力はすべて整数

**考察ノート**

可能性判断については、すべてを2と3で割れるだけ割っていって、残った配列がすべて同じ要素ならo、ちがうならx。
最小回数については、すべての要素を素因数分解したときの2の指数と3の指数を数えておき、それぞれのminとの差の合計をとればいい。

**難所**

（特になし。自力で滞りなく AC。）

**レビュー(LLM)**

1. **考察ノートの評価** — 核心は正しく押さえている。①「操作は 2・3 の指数しか下げられない」ので 2・3 を割り切った残りの核（6 と互いに素な部分）が全要素で一致するかが可能性判定、②各要素の 2 の指数・3 の指数を数え、それぞれの min との差の総和が最小回数、という 2 段構成を簡潔に言語化できている。補うとすれば「割る操作しかない＝指数は減る一方なので、そろえる先の指数は必ず min（最も少ない要素）に強制される」という最適性の根拠と、「2 の指数と 3 の指数は互いに干渉せず独立に最小化できる」という一言があると、なぜ min の和でよいかが自明になる（今回は 簡単・自力AC なので過不足なし）。

2. **弱点・思考の癖の指摘** — つまずき分類 [] で 9 分自力AC。詰まりの記録が無く、指摘すべき弱点は無い。本ディレクトリ初のノートのため過去記録との突き合わせ対象も無し。以降、同型（素因数分解・不変量への帰着）の問題が増えたら横断集計する。

3. **別解・より良い方針** — 方針自体が想定解。実装面では `can`（可能性判定で全要素を割り切る）と `calc`（指数カウント）で配列を 2 回舐めているが、1 パスにまとめられる: 各 a_i について 2 と 3 を割り切りながら指数 x_i, y_i を記録し、割り切った残り core_i も保持 → core が全一致かで可否判定、答えは Σ(x_i−min x)+Σ(y_i−min y)。計算量は変わらないが走査が 1 回で済み見通しが良い。

4. **実装の正しさ・計算量** — 問題なし。`can` は core の一致判定として正しく、`calc` の指数カウントも正しい。X=min x, Y=min y を独立に取って差の総和を出す部分も最適。計算量は 1 要素あたりの割り算が O(log a_i)、全体 O(N log A)（N≤1000, A≤10^9）で余裕。`a.size()-1`（unsigned）はアンダーフローの懸念があるが制約 N≥2 で size≥2 のため安全。値渡し（`can(vll a)` / `calc(vll a, ll t)`）でコピーしているが N≤1000 なので問題なし。

## 問題全体のメモ

操作が「特定の素因数（2,3）の指数だけを単調に減らす」型。core（2,3 と互いに素な部分）は操作で不変なので一致判定に使い、指数は減る一方なので各素数ごとに min へそろえるのが最小 —— という「不変量＋各素数の指数を独立最小化」の型。3 種以上の素因数を扱う一般化や、乗算も許す版（そろえる先が min に固定されなくなる）に注意。
