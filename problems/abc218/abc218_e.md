## 問題

N 頂点 M 辺の連結無向グラフがある。辺 i は頂点 A_i と B_i を結ぶ。
高橋君は 0 本以上の辺を取り除く。辺 i を取り除くと、C_i ≥ 0 なら報酬 C_i を得て、
C_i < 0 なら罰金 |C_i| を支払う。取り除いた後もグラフが連結であるように保ちながら、
得られる報酬の総和の最大値を求めよ。

入力:
```
N M
A_1 B_1 C_1
⋮
A_M B_M C_M
```
出力: 報酬の総和の最大値を1行で。

**制約**

- 2 ≤ N ≤ 2×10^5
- N-1 ≤ M ≤ 2×10^5
- 1 ≤ A_i, B_i ≤ N
- -10^9 ≤ C_i ≤ 10^9（**コストは負になりうる**）
- 与えられるグラフは連結
- 入力はすべて整数
- **多重辺・自己ループが存在しうる**

- felt: 簡単 # 体感は簡単だが実際は負辺ケースを見落とした（過信の兆候。difficulty 1004 との整合は取れている）

**考察ノート**

最小全域木みたいにできそう。最小全域木は、使う辺のコストの総和を最小化するアルゴリズム。
今回の場合、辺を取り除くのにコストがかかって、それを最大化したいから、やっぱり使う辺
（＝残す辺）のコストの総和を最小化したい。負の辺が使われているとまずいので、全部の辺から
最小コストを引いてから考える（最小コストがマイナスの場合、0 基準にコストを振り直す感じ）。
木を構成すると辺の本数は N-1 本となるから、答えは（全コストの総和）−（振り直した MST + 最小コスト×(N-1)）でよさそう。

【修正後】負辺は取り除いても得しない（＝必ず残す）ので、各コストを max(c,0) に潰して 0 コスト化し、
`Σ max(c,0) − MST(max(c,0))` を出力するように変更。0 辺（元・負辺）は MST が優先的に使うため、
差し引きで「取り除いた非負辺の総和」がちょうど残る。

**難所**

初回提出で 1 WA。「連結を保つ＝全域**木**を残す」と決め打ち、素の MST を残す実装にしたため、
負辺が閉路（特に多重辺・自己ループ）を成すケースを取りこぼした。連結制約が許すのは
連結な全域**部分グラフ**であり、負辺は全部残すのが最適という点を見落とした（エッジケースの見落とし）。

**レビュー(LLM)**

**① 考察ノートの評価**
「取り除く報酬の最大化 ＝ 残す辺のコスト総和の最小化」という言い換え（答え = 全コスト総和 −
残すコスト総和）に到達できている点は良い。核となる言い換えを言語化できている。
一方、「残す辺は木（N-1 本）でよい」と暗黙に決め打っている部分の根拠が書かれていない。
ここが本問の落とし穴で、後述の通り一般には成り立たない。「なぜ木でよいのか（＝負辺をどう扱うか）」
を一段掘り下げて言語化しておくと、次に同型が来たときに間違えにくい。

**② 弱点・思考の癖の指摘**
「連結を保つ＝全域“木”を残す」と反射的に木へ帰着させている。連結を保つ制約は
「連結な全域**部分グラフ**」であって木に限らない。負コスト辺は残しても総和を下げるので、
最適解では**すべての負辺を残す**のが得（木にすると余分な負辺を捨てて損をする）。
「連結制約→木」という短絡は、負辺・多重辺が絡む問題で崩れる。第1回の記録が1問目のため
過去との突き合わせはできないが、この「構造を最小構成（木）に決め打つ癖」は今後の集計対象。

**③ 別解・より良い方針（想定解）**
辺をコスト昇順にソートし Kruskal 風に走査する。
- C_i < 0 の辺：連結性に関係なく**必ず残す**（取り除くと損。report 0）。実装上は無条件に unite。
- C_i ≥ 0 の辺：両端が既に連結なら**取り除いて** C_i を報酬に加算、非連結なら残す（unite）。
答え = Σ_{取り除いた辺} C_i。これで「負辺は全部残す＋非負辺は MST 的に最小限だけ残す」が実現できる。

**④ 実装の正しさ・計算量 — 初回WA→修正で解消**
計算量は O(M log M)（ソート＋Union-Find）で一貫して問題なし。**正当性は初回提出で誤っていた**。
初回コードは「全域**木**（N-1 本）を残す」= 素の MST を残す前提で、負辺が閉路を成すと最適でなかった。
MST は各頂点対を最も安い辺で繋ぐため、**全部が負の閉路**があると最も負でない負辺を MST から
捨てる。その辺は会計上「取り除いた」扱いになり報酬が負に振れるが、正しくは残して 0 にすべきだった。
- 反例（N=2, M=2、多重辺）：頂点 1-2 に C=-5 と C=-3 の 2 辺。正解は 1 本も取り除かず報酬 **0**。
  初回コードは total=-8, mc=-5, MST=0（振り直し後）で 答え = -8 − (0 + (-5)×1) = **-3** を出力し誤答。
  → 実際にこの系統のケースで **1 WA**。制約が多重辺・自己ループ・負コストを許すため露出した。
- **修正（採用）**：各コストを `max(c,0)` に潰してから `Σ max(c,0) − MST(max(c,0))` を出力。
  負辺が 0 コスト化され MST が優先的に使う（残す）ので、③ の「負辺は全部残す」が自動的に実現される。
  上記反例も total=0, MST=0 → **0** で正答。自己ループ（正：除去で加点／負：0で無害）も正しく処理される。
  ③ の Kruskal 走査版と等価で、こちらの方が既存 `kruskal` を流用できて簡潔。**修正版は正当性・計算量とも問題なし。**
- なお（初回コードの）`mc` による全辺シフトは MST を変えない（全域木は必ず N-1 本なので定数シフト不変）。
  正当性に無関係で負辺閉路の問題も解消しなかった。max(c,0) 方式ではシフトは不要になり削除されている。

## 問題全体のメモ

本質は「取り除く報酬の最大化 ⇔ 残す連結部分グラフのコスト最小化」。
残すのは木とは限らず、**負辺は全部残す＋非負辺は MST 最小限**が最適。
自作ライブラリの `kruskal`（library 相当が honban に同梱）は「全域木のコスト」を返す実装のため、
本問のように「負辺を捨てない」要件があるとそのままでは使えない。用途に応じて
「負辺無条件 unite → 非負辺は同一成分なら報酬計上」の走査を別途書く必要がある。
