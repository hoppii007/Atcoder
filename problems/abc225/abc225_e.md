## 問題

第一象限に N 個の「フの字」がある。i 個目のフの字は、点 (x_i−1, y_i) と (x_i, y_i) を結ぶ線分と、
点 (x_i, y_i−1) と (x_i, y_i) を結ぶ線分を組み合わせた図形である。

N 個のフの字から 0 個以上を選んで削除する。適切に削除したとき、原点から全体が見えるフの字の個数の最大値を求めよ。

i 個目のフの字が原点から全体が見えるとは、原点・(x_i−1, y_i)・(x_i, y_i)・(x_i, y_i−1) を頂点とする四角形の
内部（境界を除く）が、他のフの字と共通部分を持たないことをいう。

入力:

```
N
x_1 y_1
⋮
x_N y_N
```

出力: 原点から全体が見えるフの字の個数の最大値。

**制約**

- 1 ≤ N ≤ 2×10^5
- 1 ≤ x_i, y_i ≤ 10^9
- i ≠ j のとき (x_i, y_i) ≠ (x_j, y_j)
- 入力はすべて整数

**問題の核**

- フの字 i が見える ⇔ 原点から見た偏角区間 [arg(x_i, y_i−1), arg(x_i−1, y_i)] が、残した他のフの字の区間と**内部で**重ならない。
  → 端点の接触を許す区間スケジューリング（終端の早い順に貪欲）。
- 偏角は外積で厳密比較し（atan2 を使わない）、**同じ偏角は同じ値**として扱う。

**会話から残すこと**

（解説の会話はこのセッションの外で行われたため、コードの差分と作成されたライブラリから分かる範囲で記す）

- ソート後の位置 i を「順位」として使うと、比較で同値な要素同士の順序が不定になり、等号を含む判定（`t <= start`）が壊れる。
  同値を同じ番号にまとめるには `coordinate_compression(a, comp)` を使う（comp 版はこのために [abc481_f](../abc481/abc481_f.md) で追加済み）。
- `library/interval_scheduling.cpp` を新規作成。`is_pittari_ok` で端点接触の可否を切り替え、
  @note に「偏角などを区間にするときは coordinate_compression(a, comp) で番号付けすること」を明記。

**難所**

- 1 回目の提出が WA。方針は正しく、原因は番号付けの1箇所。
- 偏角ソート後に `idx[ps[i]] = i`（ソート後の位置）で番号を振っていたため、偏角が等しい別の点（例: (1,1) と (2,2)）に
  異なる番号が付き、その大小は std::sort の不定な並びに依存した。ある区間の終点と別の区間の始点が同じ偏角のとき
  （接触なので両方選べるべき）、始点の番号 < 終点の番号となると `t <= start` が偽になり、選べる区間を取りこぼす。
  例: N=2, (2,1), (2,3)。区間は [arg(2,0), arg(1,1)] と [arg(2,2), arg(1,3)] で、arg(1,1) = arg(2,2)。答え 2 だが、
  (2,2) が (1,1) より前に並ぶと 1 になる。
- 修正: 偏角が等しい点に同じ番号を振る（`is_same_arg` で判定、のちに `coordinate_compression(ps, arg_comp)` へ置換）で AC。

**レビュー(LLM)**

1. **考察の評価** — 方針決定までの言語化は具体的で、偏角→区間→区間スケジューリング→端点の作り方、の順に段階を踏めている。
   欠けているのは「判定条件の等号」: 問題文の「内部（境界を除く）」が「端点の接触は OK」を意味すること、
   したがって偏角の等しい端点は等しい値として比べなければならないこと。区間スケジューリング系では
   「接触は OK か NG か」を方針確定時に1行書く習慣を付けると、今回の種類のバグはログの段階で潰れる。
   WA 後のログには仮説を最低1つ書いてから解説に移ると、自己診断の精度が記録に残る。
2. **弱点・思考の癖** — つまずき分類 `実装バグ` はこれで 8 件目（[abc212_f](../abc212/abc212_f.md), [abc213_d](../abc213/abc213_d.md),
   [abc242_d](../abc242/abc242_d.md), [abc246_d](../abc246/abc246_d.md), [abc267_d](../abc267/abc267_d.md),
   [abc301_e](../abc301/abc301_e.md), [abc481_f](../abc481/abc481_f.md), 本問）で、突出した最多分類。
   特に [abc481_f](../abc481/abc481_f.md) と本問は同型: **ソート後の列にランク（番号）を手で振る処理で、同値の扱いを誤って WA**。
   abc481_f では「ランクを進める判定がフィルタの内側にあった」、本問では「同値でも番号を進めていた」。
   どちらも修正は `coordinate_compression(a, comp)` への置き換え。「ソート後に番号を振るときは手書きせず座標圧縮ライブラリを使う」
   を固定ルールにする根拠が 2 件揃った。また両問とも方針は自力で正しく立っており、`解説AC` の原因は方針でなく実装の1箇所である点も共通。
3. **別解・より良い方針** — 座標圧縮を挟まず、区間を (始点ベクトル, 終点ベクトル) のまま持ち、終点を外積比較でソートし、
   「前の終点 ≤ 次の始点」も外積（cross ≥ 0）で直接判定する書き方もある（公式解説の分数比較と同等）。
   番号付けの工程そのものが無くなるため、本問のバグは原理的に起きない。
   atan2 を使う方法は座標 10^9 だと隣接偏角の差が ~10^-18 になり double では区別できないため不可。
4. **実装の正しさ・計算量** — 最終コード（005）は問題なし。端点 (x−1, y), (x, y−1) は x, y ≥ 1 より (0,0) にならず、
   すべて偏角 [0, π/2] に入る。外積は |x|,|y| ≤ 10^9 で最大 ~10^18 で ll に収まる。始点の偏角 ≤ 終点の偏角も成り立つ。
   O(N log N)。座標圧縮の map を `idx[...]` で引いているが、キーは必ず存在するので要素の追加は起きない（`at` でも可）。
   推移で直した誤り: 003 の番号付け（難所参照）。
