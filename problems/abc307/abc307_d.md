## 問題

英小文字と括弧 `(` `)` からなる長さ N の文字列 S が与えられる。次の操作を、
できなくなるまで繰り返す。

「`(` で始まり `)` で終わり、その両端以外に括弧を含まない連続部分文字列を選んで削除する」

最終的に得られる文字列を出力する。操作順によらず結果は一意に定まる。

**制約**

- 1 ≤ N ≤ 2×10^5
- N は整数
- S は英小文字と `(` `)` からなる
- 操作順によらず最終結果は一意に定まる

入力は `N` / `S` の2行、出力は操作後の文字列（空になり得る）。

**考察ノート**

文字列を `()` で囲う系なので、スタックでいけそう。
現在までの「未対応の `(`」の個数を持っておいて、`)` を見つけたら直近の `(` まで
消していく、とかでよさそう。

**難所**

難所というほどではないが、配列の最後の要素を取るのに `a.rend()` としてしまって
ちょっと時間を使ってしまった（正しくは `a.rbegin()`）。凡ミス。

**レビュー(LLM)**

① 考察ノートの評価 — 方針の核（「未対応の `(` の個数を持つ」→ `)` で直近の `(` まで pop）は
簡潔に言語化できている。なぜスタックで十分か（`)` に対応する `(` は必ず「直近の未対応 `(`」で、
その間には括弧が残っていない＝letter だけ）まで一言添えると、他の括弧列問題への転用が効く。

② 弱点・思考の癖 — つまずき無し。`a.rend()`/`a.rbegin()` の取り違えは自己修正済みの凡ミスで、
統制語彙で拾うほどの反復パターンではないため つまずき分類は []。

③ 別解・より良い方針 — スタックによる本解が最も素直で最適。`cnt`（未対応 `(` 数）を持たず
「スタック内に `(` があるか」を都度判定する変形も可能だが、`cnt` の O(1) 判定の方がきれい。
本質的により良い解法は無い。

④ 実装の正しさ・計算量 — 問題なし。`cnt` は現在スタック `a` に積まれている未対応 `(` の数。
`)` 到来時に `cnt>0` のときだけ `while(*a.rbegin()!='(')` で pop するので、ガードにより
アンダーフローしない。各文字は高々1回 push / 1回 pop され O(N)。サンプル4種
（`a(b(d))c`→`ac`、`a(b)(`→`a(`、`()`→空、`)))(((`→`)))(((`）を追跡して一致を確認。
`cinll(n)` の `n` は未使用で `s.size()` を使っているが動作に影響なし。

## 問題全体のメモ

括弧の対応をスタックで追い、閉じで直近の開きまで巻き戻す典型。開き数カウンタ `cnt` で
「対応する開きが存在するか」を O(1) 判定するのがポイント。
