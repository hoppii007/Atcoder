## 問題

長さ N の整数列 A = (A_1, A_2, ..., A_N) が与えられる。
長さ M の A の部分列（連続でなくてもよい）B = (B_1, B_2, ..., B_M) に対する Σ_{i=1}^{M} i × B_i の最大値を求めよ。

（部分列：数列から 0 個以上の要素を取り除き、残りを元の順序で連結して得られる数列）

入力: `N M` / `A_1 A_2 ... A_N`
出力: 答え

**制約**

- 1 ≤ M ≤ N ≤ 2000
- −2 × 10^5 ≤ A_i ≤ 2 × 10^5
- 入力は全て整数

## 挑戦履歴

### 第1回 — 2026-11-17

- solved: 自力AC
- time_spent_min: 29

**自分の考察**

a[i]を選ぶかどうかの選択として、選んだらそれより先のやつらがすべて二倍というか、i<jの中で選んでいる場所がすべてa[j]足される、みたいなことになる。

あー、
dp[i][j] := i番目まででj個選ぶ時の最大値、みたいな風にすれば、
dp[i][j] = max(dp[i-1][j], dp[i-1][j-1]+j*a[i]) で更新できるか


発想としてはよかったが、dpの境界処理で落ちて、デバッグに時間を使った...絶対に無理の個所と0で初期化する箇所の境界があいまい

**問題の核**

- 部分列の j 番目に置く要素の係数は j。なので「前から i 個見て、そのうち j 個選んだ」を状態にすると、次に選ぶ要素の係数が j+1 に決まる。
- dp[i][j] = max(選ばない: dp[i−1][j], 選ぶ: dp[i−1][j−1] + j·A_i)。O(NM) = 4×10^6。
- A_i が負になりうるので、到達できない状態（j > i）は 0 ではなく −inf にしておく。0 にすると「j 個選んだ」ことになっていない状態から答えが作られる。

**会話から残すこと**

- **ちょうど K 個選ぶ最大化 DP の初期化**：到達できる状態は dp[i][0] = 0 だけで、それ以外の初期値は −inf。値に負がある問題では、0 で初期化すると「選ばない＝0」と「到達できない」が区別できなくなる。
- **愚直解は答えの定義を本解と揃える**：個数の条件（idx == m）と答えの初期値（−inf）が本解と違うと、比較しても意味がない。今回は「空集合なら 0 にできる」という見方で、一度 ans = 0 のままにしかけた。m ≥ 1 なので空集合は候補に入らない。
- **ライブラリ修正**：[bit_bruteforce.cpp](../../library/Math/bin/bit_bruteforce.cpp) はループ範囲が逆（外側 `rep(state,n)`／内側 `rep(bitj,1LL<<n)`）で、展開すると a[bitj] で範囲外アクセスになっていた。外側を `1LL<<n`、内側を `n` に直し、スニペットも作り直した。

**難所**

- 方針（状態と遷移）は自分の考察の段階で正しく立っていた。時間の大半は DP の初期値で使った。
- 最初の solve は `vvll dp(n+1, vll(m+1, 0))` で全体を 0 初期化していた。途中で `-inf` 初期化にしたものの `rep(j, m+1) dp[0][j] = 0;` を残していて、i = 0 で j ≥ 1 の到達できない状態がまだ 0 だった。A が負のとき、本当の値より大きい値になる。提出版は `dp[0][0] = 0`、`dp[i][0] = 0` だけにして AC。
- 愚直解 greedy を書くときに、bit 全探索のスニペット自体のバグ（ループ範囲が逆）で `vector::operator[]` の assert に落ち、ストレステストの立ち上げにも時間を使った。
- 本人の言葉では「絶対に無理の個所と0で初期化する箇所の境界があいまい」。

**レビュー(LLM)**

① **考察の評価**：状態 dp[i][j] と遷移を自分で言語化できている。「選んだ要素の係数は、それまでに選んだ個数で決まる」という気づきが鍵だが、書き方が「先のやつらがすべて二倍というか…」と揺れている。「j 番目に選ぶ要素の係数は j → 選んだ個数を状態に持てば係数が決まる」と一文にすると、状態設計の根拠になる。初期化については「あいまい」と自覚までは書けている。次は「−inf にすべき状態の判定基準＝その (i, j) に実際に到達できる選び方があるか」まで書けるとよい。

② **弱点・思考の癖**：考察は正しいのに、実装の境界で落ちて時間を使うパターンが繰り返し出ている。[abc212_f](../abc212/abc212_f.md)（境界処理で WA。「状態設計・遷移の考察は正しいのに、出力整形・添字変換・定数倍で落とす」と記録済み）、[abc213_d](../abc213/abc213_d.md)（木 DFS の境界ずれ、実装バグ）、[abc246_d](../abc246/abc246_d.md)（[実装バグ, デバッグ]、今回と同じ分類）。今回は DP の初期値、つまり「到達できない状態と値 0 の状態を区別する」点で起きた。DP の状態を書くときに、初期値（どの状態が到達可能か）まで一緒に言語化していないことが原因と読める。tags.md の DP の備考にある「状態設計→遷移→初期値の順で言語化」の、3つ目が抜けている。

③ **別解・より良い方針**：想定解はこの O(NM) DP。dp を 1 次元にして j を降順に更新すればメモリを O(M) にできるが、N, M ≤ 2000 なので不要。`if(j == m) chmax(ans, ...)` は「選ばない」遷移で dp[n][m] に最大値が運ばれるので、`dp[n][m]` を出力するだけでよい。

④ **実装の正しさ・計算量**：提出版は正しい。`i+1 < j` を飛ばしているので、dp[i][j−1] は常に到達可能な状態から読まれる。−inf になりうるのは dp[i][j]（j = i+1）だけで、これは max で比べるだけで値を足さない。そもそも inf = 1.3×10^18 なので、仮に −inf に ±4×10^8 程度を足してもオーバーフローはしない。計算量 O(NM) ≈ 4×10^6 で問題なし。submit.cpp に使っていない greedy が残っているが、提出には影響しない。

## 問題全体のメモ

- 「ちょうど M 個選ぶ」DP の初期化：dp[i][0] = 0、それ以外は −inf。答えは dp[N][M]。
- 愚直解（bit 全探索で、ちょうど M 個の部分集合だけを見る、ans = −inf から始める）とのランダム比較で、初期化のバグを見つけた。
