## 問題

1〜N の番号が振られた N 個の都市と、それらの間を運行する M 本のバスがある。i 本目のバスは
時刻 S_i+0.5 に都市 A_i を出発し、時刻 T_i+0.5 に都市 B_i に到着する。高橋くんは時刻 t に都市 p に
いるとき次のように行動する:

- 時刻 t 以降に都市 p を出発するバスが存在するなら、最も出発時刻が早いものに乗る。
- そのようなバスが存在しないなら、都市 p に居続ける。

Q 個のクエリに答える。各クエリは、時刻 X_i に都市 Y_i から行動を開始したとき、時刻 Z_i に
高橋くんがどの都市にいるか、あるいはどのバスに乗っているかを問う。

入力形式:
```
N M Q
A_1 B_1 S_1 T_1
  ⋮
A_M B_M S_M T_M
X_1 Y_1 Z_1
  ⋮
X_Q Y_Q Z_Q
```

**制約**

- 2 ≤ N ≤ 10^5
- 1 ≤ M ≤ 10^5
- 1 ≤ Q ≤ 10^5
- 1 ≤ A_i, B_i ≤ N、A_i ≠ B_i
- 1 ≤ S_i < T_i ≤ 10^9
- S_i ≠ S_j (i ≠ j)
- 1 ≤ X_i < Z_i ≤ 10^9
- 1 ≤ Y_i ≤ N
- 入力は全て整数

**考察ノート**

Zの制約が小さければ、クエリを小さい順に並び替えた後にその時刻にどこにいるかをシミュレートしていけば良さそうだが、Zがデカい。
クエリを時刻小さい順に並べれば、自分の状態としてあり得るのは「どこかの都市にいるか、どこかのバスにいるか」なので N+M 個しか状態がない。
状態の切り替わりのタイミングだけ記録しつつ進めばいい…と思ったが、これはスタート地点が固定されている場合。
クエリをスタート地点ごとに分割する手もあるが、スタート候補が N 個 × その後の状態 N+M 個で O(N(N+M)) になりダメそう。

グラフの拡張で何とかできないか。「頂点 a を時刻 p に出発するバス」を一つの頂点とし、
(a,p) -> (a', t 以降で最初に a' からバスが出る時間) としておくと、すべての状態から行き先が一意に決まる。
そうするとダブリングが使えて、すべての場所・時刻から N 回進んだ先が記録でき、それを使って二分探索で初めて Z を超える場所を探せばいい。

考慮すべき頂点はバスの本数しかない（各バスの場所と開始時刻を頂点とするため）。整理すると:
頂点集合 S = {(s_i, t_i) | s_i = i番目のバスの出発都市, t_i = i番目のバスの出発時刻}、|S| = M。
各頂点から辺 (s_i, t_i) -> (s'_i, t'_i)（s'_i = バス i の到着都市, t'_i = 到着時刻以降で最初に出発するバスの時刻、無ければ inf）を張ると |E| = M。
この上でダブリングを行う計算量は |S| * log(パス最大長) = M log M で間に合う。
各クエリでは、最初に出発する都市 a と時刻 p を求め、(a,p) から進んだ頂点で初めて p' が z を超える箇所を二分探索で探し、
その手前の頂点から (a', p') への道中で、時刻 Z に「バスに乗っているのか a' で待機しているのか」を判断すればよい。

**難所**

考察も難しいが、グラフの拡張系のひらめきは得意で、思ったより早めに方針は立った。そこからの実装がかなり重かった。
提出後、TLE と大量の WA。TLE は定数倍（後述）、WA は境界処理由来。

**レビュー(LLM)**

1. **考察ノートの評価** — 十分。核心（状態が N+M 個で有限 → 遷移を一意化して functional graph 化 → ダブリング → 二分探索で Z 超えを探索）が段階的に言語化できており、計算量 M log M の見積もりも明示。「都市×出発時刻を1頂点にする」拡張の発想と、遷移一意化の条件（到着時刻以降で最初のバス）まで詰められている点が良い。想定解と一致。

2. **弱点・思考の癖** — 「方針は速いが実装で溶かす」型が今回も出た（本人の難所コメントと一致）。今回の詰まりは2点に分解できる:
   - **定数倍への無頓着で TLE**: `endl` による毎クエリのフラッシュ（Q≤10^5）、高速IO 未設定、`to_idx`（4フィールド struct をキーにした map）を二分探索ラムダの内側で毎回引く（1クエリ約60回）。いずれもアルゴリズムではなく定数の問題。漸近計算量 M log M は正しく見積もれているのに、間に合う実装かの詰めが甘い。
   - **境界処理で WA**: 出力の内部番号／都市番号変換の取りこぼし（`bus2.b` を +1 も変換もせず生出力していた箇所, main.cpp:317 相当）、`ok==0`（一度も出発しない）分岐の扱い。
   「状態設計・遷移の考察は正しいのに、出力整形・添字変換・定数倍で落とす」という癖として記録。過去ノートが揃ったら再挑戦時に同じ分類が再発するか要追跡。

3. **別解・より良い方針** — 方針は想定解。実装面のみ:
   - 二分探索の上限を `inf`(10^18) ではなくノード数（M+N ≒ 2×10^5）にすれば、二分探索60回×60ビット走査 → 18×18 に削減（約10倍）。
   - 「二分探索 × ダブリング（O(log²)）」をやめ、ダブリングを上位ビットから貪欲に降りる（LCA と同じ要領, O(log)）とより速く簡潔。
   - `map<Bus,ll>` は不要。バスに自分の添字を持たせる／`nexts` 構築時に lower_bound 結果を添字で保持すれば map ごと消せる。

4. **実装の正しさ・計算量** — 漸近計算量は O((N+M) log K + Q(log K)²) で正当。修正後 AC。当初 TLE の主因は上記2(定数倍)。ダブリングテーブルは `LOG=60` 固定で n=2×10^5 だと約97MB とやや重く、上限をノード数基準にすれば `LOG≈18` で30MB 程度に減らせる（今回は範囲内）。`nexts` は inf ノードを自己ループにしているため kth_next が -1 を返さず、`buses[...]` の範囲外参照は起きない設計になっている点は良い。

## 問題全体のメモ

「状態が有限個 → 遷移を一意化して functional graph → ダブリングで K 回先 → 二分探索/貪欲で条件初到達を探索」は再利用性の高い型。
関連ライブラリ: `Doubling`（honban/main.cpp 内に実装、kth_next / kth_next_all）。二分探索併用より貪欲降下版があると本問のようなケースで速い。
