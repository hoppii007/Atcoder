## 問題

2 次元平面に N 個の街と M 個の宝箱がある。街 i は座標 (X_i, Y_i)、宝箱 i は座標 (P_i, Q_i) にある。
高橋君は原点を出発し、N 個の街すべてを訪れてから原点に戻る旅行をする。宝箱は訪れなくてもよいが、
各宝箱にはブースターが 1 つ入っており、拾うたびに移動速度が 2 倍になる。最初の移動速度は単位時間あたり 1。
旅行にかかる時間の最小値を求めよ。

**入力**

```
N M
X_1 Y_1
⋮
X_N Y_N
P_1 Q_1
⋮
P_M Q_M
```

**出力**

答えを出力せよ。想定解答との絶対誤差または相対誤差が 10^{-6} 以下であれば正解。

**制約**

- 1 ≤ N ≤ 12
- 0 ≤ M ≤ 5
- -10^9 ≤ X_i, Y_i, P_i, Q_i ≤ 10^9
- (0,0), (X_i,Y_i), (P_i,Q_i) は相異なる
- 入力は全て整数

**問題の核**

- 宝箱を含む N+M ≤ 17 点を全部頂点にした TSP（bitDP）にすると、現在速度は「state に含まれる宝箱の個数 k」だけで決まり 2^k。
  遷移コストは 距離 / 2^{popcount(state の宝箱部分)}。
- 答えは「街のビットがすべて立った state」全体で `dp[state][j] + |p_j| / 速度(state)` の最小（宝箱を取るかは state の自由度に含まれる）。

**難所**

  修正途中で `((1<<m)-1) << n`（宝箱側）も経由している。
- 初版の速度計算が `rep(i, N)`（街のビット）を数えていた（初ビルド前に修正）。
- `spd` を関数化したとき、関数名と同名のローカル変数を改名し漏れ、`/ spd` が関数名を指してコンパイルエラー。
- 不一致の原因探しで、直前に書いた集計部ではなく dp テーブルの中身から検証を始め、約 8 分かかった。

## 問題全体のメモ

- 「TSP だが移動コストがそれまでに訪れた集合で変わる」型。bitDP の state が訪問集合そのものなので、コストが state の関数でも
  遷移元 state を見れば計算できる（2^k 倍速、所持品による重量変化など）。
- 任意で訪れる点（宝箱）は頂点に含めておき、集計時に「必須点のビットが全部立っている」state だけを見る。
- 実数出力は `fixed << setprecision(15)`。座標が 10^9 のとき既定の有効数字 6 桁では誤差 10^{-6} を満たさない。
