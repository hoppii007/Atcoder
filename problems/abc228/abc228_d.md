## 問題

長さ N = 2^20 の数列 A = (A_0, …, A_{N-1}) があり、初めすべての要素は -1 である。
Q 個のクエリを順に処理する。i 番目のクエリは t_i と x_i で表される。

- t_i = 1 のとき: h = x_i とし、A_{h mod N} ≠ -1 である間 h に 1 を足し続ける。その後 A_{h mod N} を x_i で書き換える（この操作が有限回で終わることは制約下で証明できる）。
- t_i = 2 のとき: その時点での A_{x_i mod N} の値を出力する。

N = 2^20 = 1048576 は入力では与えられない。

### 制約

- 1 ≤ Q ≤ 2 × 10^5
- t_i ∈ {1, 2} (1 ≤ i ≤ Q)
- 0 ≤ x_i ≤ 10^18 (1 ≤ i ≤ Q)
- t_i = 2 を満たす i が 1 つ以上存在する
- 入力はすべて整数である

### 入力

```
Q
t_1 x_1
⋮
t_Q x_Q
```

### 出力

t_i = 2 である各クエリについて、答えを 1 行ずつ出力する。

**問題の核**

- 「h から右へ最初の空き」を毎回線形に探すと O(NQ)。埋まった位置 i を i+1 に繋ぎ、根＝次の空きとする（向きを右に固定した Union-Find／経路圧縮つきの next ポインタ）とならし高速。
- 配列は円環（mod N）。添字の入口（h = x mod N）・遷移（i+1 → (i+1) mod N）・参照（A_{x mod N}）の 3 か所すべてで mod を取る。

**会話から残すこと**

- 「次の空き」型では、成分の最大要素を集合で持つより、併合の向きを固定して根そのものを次の空きにする方が軽い（set を 2^20 個持つ必要が無い）。汎用の union_find（サイズで併合の向きを決める）では根が最大になるとは限らないため、この型には向かない。
- 既存の union_find を変えずに解く方法は2つある。(a) 隣どうししか併合しないので成分は常に区間になり、`is_same(h, m)` が m について単調になる。これを使って二分探索で区間の右端（＝次の空き）を求める（クエリあたり O(log N)、状態を足す必要なし。一周しないよう N+1 個で作り、右端が番兵 N なら 0 から探し直す）。(b) main 側に `empty_of[root]` を持つ。i を埋めたら unite(i, (i+1)%N) の前に `e = empty_of[root((i+1)%N)]` を取り、併合後に `empty_of[root(i)] = e` とする。各成分の空きは右端の1つだけ、という性質を使う。mod で併合するので一周しても特別扱いが要らない。一方「成分の最大値」を持つ方法は、一周すると最大値が空きの位置にならないため、0 から探し直す場合分けが必要になる。本人が分かりやすいと感じたのはこの最大値の方式で、要素を N+1 個（番兵 N）にし、根ごとの最大値を main 側の配列で持ち、最大値が N なら root(0) の成分の最大値を答えにする。
- ライブラリを少しだけ変えたいとき: まず include したまま外側に配列を足して済まないか考える。済まなければ main に貼って変える（ライブラリ本体は解いている最中に触らない）。同じ改変を何度も貼るようなら、解いた後でライブラリに足す。
- 解いている最中にライブラリの型を変えると、ライブラリ自身や既存の利用箇所が壊れたまま残りやすい。今回の union_find の変更は元に戻した。
