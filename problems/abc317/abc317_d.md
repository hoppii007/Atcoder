## 問題

高橋君と青木君が選挙で争う。選挙区は N 個あり、選挙区 i には X_i + Y_i 人の有権者がいる。
そのうち X_i 人が高橋派、Y_i 人が青木派である（X_i + Y_i は奇数）。
各選挙区では、多数派の側がその区の Z_i 議席をすべて獲得する。全 N 区の議席の過半数を得た側が選挙に勝つ
（Z_i の総和は奇数）。

高橋君が選挙に勝つためには、最低何人の青木派の有権者を高橋派に鞍替えさせる必要があるかを求めよ。

**入力**

```
N
X_1 Y_1 Z_1
X_2 Y_2 Z_2
⋮
X_N Y_N Z_N
```

**出力**

答えを 1 行で出力する。

（例：`1` / `3 8 1` → `3`。`2` / `3 6 2` / `1 8 5` → `4`。`3` / `3 4 2` / `1 2 3` / `7 2 6` → `0`）

**制約**

- 1 ≤ N ≤ 100
- 0 ≤ X_i, Y_i ≤ 10^9
- X_i + Y_i は奇数
- 1 ≤ Z_i
- Σ_{i=1}^N Z_i ≤ 10^5
- Σ_{i=1}^N Z_i は奇数
- 入力は全て整数

**問題の核**

- 負けている区 i を取るコスト = ceil((Y_i−X_i)/2) 人、得られる議席 = Z_i → 「必要議席数以上を最小コストで」の 0-1 ナップサック。
- 重さ（人数）は最大 ~10^9 だが価値（議席）の合計は ≤ 10^5 → **添字を価値にして最小重さを持つ** ナップサック。
  これ1回の DP で答え（必要議席を満たす j のうち最小の dp 値）が出るので、二分探索は不要。

**会話から残すこと**

- レビュー後に本人が言語化：「必要な最小議席数 need が先に分かるので、knapsack2 の dp をそのまま返して
  dp[n-1][need 以上] の最小を取ればよい」。答えを二分探索する前に、判定の中身（ここでは最適値 DP）が
  答えを直接与えていないかを確かめる、という一般化。
- 「ちょうど」版なら min_{j ≥ need} dp[j]、「以上」版なら dp[N][need] 一発。両者の差は遷移で `dp[max(0, j − v)]` を見るかどうかだけ
  （[library/dp/knapsack.cpp](../../library/dp/knapsack.cpp) は「以上」版）。
- 「以上」版が合わなかった原因（本人の質問への回答）: 初期値の不等号の向きが逆だった。「価値 j 以上」を品 0 だけで満たせるのは
  **j ≤ v[0]** のときなのに、`j ≥ v[0]` に w[0] を入れていた（品 0 が入るのは j ≥ w[0] という「容量 j 以下」側の形をそのまま流用）。
  45:51 の時点で `+w[i]` と dp[i][0] = 0 は直っていたが、初期値の向きが残っていたため入力例 2 で dp[1][7] = 2（本当は 6）となり、
  答えが 4 でなく 2 になった。もう1つの不整合は `j < v[i]` で遷移しないこと（「以上」なら dp[i-1][0] + w[i] で達成できる）。
  定義の修飾語（以下 / 以上 / ちょうど）ごとに、「品 1 個だけで状態 j が達成できる条件」を不等号で書き出してから初期値を書く。
  同じ回の knapsack（容量版）も `rep(i, min(w[0], H)+1)` と向きが逆で、2関数とも不等号が反転していた。
- 「品 0 の行」を手で埋めるのは、遷移を頭の中で 1 回手計算してコードと二重に書くことと同じ（2 箇所が食い違うとバグ）。
  初期値は「1 個も選ばない行」dp[0] だけを手で書き、品 0 の行はループに計算させる。dp[0] の決め方は機械的で、
  **重さ 0・価値 0 を定義の不等号に代入する**だけ：以下（0 ≤ j）→ 全 j で可能 / 以上（0 ≥ j）→ j = 0 だけ / ちょうど（0 = j）→ j = 0 だけ。

**難所**

- knapsack2 を「価値の合計を j 以上にする最小の重さ」と定義したのに、遷移を `dp[i-1][j-v[i]]`（`+w[i]` 無し、`j < v[i]` では遷移しない）、
  初期値を `dp[0][j] = w[0] (j ≥ v[0])` かつ dp[i][0] 未設定で書いた。どちらも「以上」の定義と不整合。
  定義を「ちょうど j」に変え、初期値 `dp[0][v[0]] = w[0]`・`dp[i][0] = 0`、遷移に `+w[i]` を入れて解決。デバッグ約 11 分。
- 判定関数の中で毎回 O(N·ΣZ)（最大 10^7、80MB 確保）の DP を作り直す二分探索にしたため、上界 `inf` で約 61 回呼んで TLE（本人の申告）。
  上界を 10^12 にして約 40 回に減らして AC。

4 問とも方針と状態の大枠は自力で正しく立っており、外れるのは「定義の修飾語（以下/以上/ちょうど）に合わせて初期値・遷移・答えを導く」工程。

もう一つ、計算量の見積もりで外側の反復回数（二分探索の log）を掛けていない点は、[abc212_f](../abc212/abc212_f.md)（TLE、定数倍）と同じく

③ **別解・より良い方針**: 二分探索をやめ、DP を 1 回だけ作って答えを直接取る。必要議席 need = (ΣZ+1)/2 − takz（≤ 0 なら 0）。
- 「ちょうど」版のまま: 答え = min_{j ≥ need} dp[n−1][j]。O(N·ΣZ)。
- 「以上」版: `dp[j]` = 価値を j 以上にする最小重さ、`dp[0] = 0`、他 inf、各品について j を降順に
  `dp[j] = min(dp[j], dp[max(0, j − v)] + w)`。答え = dp[need]。1次元配列で済み、メモリも O(ΣZ)。
いずれも 10^7 程度の演算で、今回の提出（約 40 回 × 10^7 + 毎回 80MB 確保）より 40 倍程度速い。

  今のままでは容量 w[0] 未満で v[0] が取れてしまう。ライブラリ化する前に直す必要がある。
