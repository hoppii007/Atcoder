## 問題

N 頂点 M 辺の有向グラフが与えられる。頂点には 1, 2, …, N の番号が付いている。
i 番目の辺は頂点 A_i から頂点 B_i へ向かう辺で、1 以上 9 以下の数字 C_i が書かれている。

辺の向きに従って移動するとき、通った辺に書かれた数字を通った順につなげて得られる整数を、その移動のスコアと呼ぶ
（例：通った辺の数字が順に 3, 1, 4 ならスコアは 314）。同じ頂点や辺を複数回通ってもよい。

v = 2, 3, …, N のそれぞれについて、頂点 1 から頂点 v へ移動するときのスコアの最小値を 998244353 で割った余りを求めよ。
入力のグラフは、頂点 1 から他のすべての頂点へ辺の向きに従って移動できることが保証される（多重辺・自己ループあり）。

入力:
```
N M
A_1 B_1 C_1
⋮
A_M B_M C_M
```
出力: N−1 行。v−1 行目に頂点 v の答え（998244353 で割った余り）。

**制約**

- 2 ≤ N ≤ 2×10^5
- N−1 ≤ M ≤ 2×10^5
- 1 ≤ A_i, B_i ≤ N
- 1 ≤ C_i ≤ 9
- 入力される値はすべて整数
- 頂点 1 から他のすべての頂点へ、辺の向きに従って移動できる

**問題の核**

- 辺の数字は 1〜9 で 0 が無いので、桁数（辺の本数）が少ないほどスコアが小さい → 最小スコアの経路は辺数最小で、BFS の層＝桁数。
- 同じ層の文字列は長さが揃っているので、文字列の辞書順 ＝ (前の層での文字列のランク, 辺の数字) の組の辞書順。
  組でソートしてランクを振り直せば、長い文字列を持たずに層ごとに比較できる。

**会話から残すこと**

- **ランク付けとフィルタ（確定済みの頂点を飛ばす）を同じループに混ぜない。** ソート済み配列全体にランクを振ってから
  フィルタする。この分離のために `coordinate_compression` に比較関数を渡せるよう一般化した
  （[coordinate_compression.cpp](../../library/Math/coordinate_compression.cpp)、返り値は `map<T,ll,Comp>`。
  comp で同値な別の要素で引いても同じ番号が返る）。
- 「(前のランク, 次の文字) の組でランクを振り直す」は、接尾辞配列のダブリング（[[abc213_f]]）と同じ原理。
  違いは伸び方だけ（ダブリングは長さ k→2k、今回は層ごとに k→k+1）。
- この方法が効く条件は2つ: (1) 各文字列が「ランク済みの文字列 + 1文字」の形で作られる構造がある
  （経路・トライ・DP の遷移）、(2) 比べる文字列の長さが揃っている。
  互いに無関係な文字列が列挙済みなら、普通のソート／`coordinate_compression` で十分で、この方法の得は無い。
  列挙済みで接頭辞の共有が多いなら、トライを子の文字順に DFS した順がそのまま辞書順（O(総文字数)）。
- 「層ごとに処理する BFS」の雛形は作らないと判断した（BFS を含むノートは 2 件で、層ごとの処理をした記録はまだ無い）。

**難所**

- 1回目の提出が WA。方針（層ごとの BFS + ランク付け）は正しく、原因は1箇所の実装バグ。
- ランクを進める判定 `if(i > 0 && nxts[i-1].p < nxts[i].p) idx++;` が `if(ans[e.v] == -inf)` の内側にあった。
  直前の要素が確定済みの頂点への候補で飛ばされると、そこで起きるべき idx の増加も飛ばされ、
  文字列の異なる頂点に同じランクが付く。
- 反例（Claude が作成）: `4 5 / 1 2 1 / 1 2 2 / 1 3 2 / 2 4 5 / 3 4 1`。
  ソート後 (rank0,1)→2 確定, (rank0,2)→2 スキップ, (rank0,2)→3 が rank0 になり、頂点 4 の答えが 15 ではなく 21 になる。
- 修正: `coordinate_compression(nxts, compf)` でランクをフィルタと独立に求める形に書き換えて AC。

**レビュー(LLM)**

1. **考察の評価** — 自分の考察は記入なしのため、本人がどの制約から方針を決めたかは記録から追えない。
   実装は層ごとの BFS になっているので「C_i ≥ 1 ⇒ 桁数が先に決まる」は捉えていたと読めるが、
   これは実装からの推測であって本人の言語化ではない。この問題で残すべき鍵は「C_i に 0 が無い」という制約と、
   「同じ長さに揃えれば (前のランク, 文字) で比較できる」の2点。次回からはパネルの「自分の考察」に書く。

2. **弱点・思考の癖の指摘** — つまずき分類 `実装バグ` はこれで 4 件目
   （[[abc213_d]]、[[abc246_d]]、[[abc212_f]]、本問）。記録のある回の中で最多の分類。
   本問と [[abc213_d]] には共通点がある: 方針は正しいまま、条件判定を「近道」で書いて特殊な入力構造で崩れている
   （abc213_d は「子が無い」を `nexts[i].size() == 1` で代用してパスグラフで破綻、本問は「値が切り替わった」を
   「直前の要素と比較」で判定し、直前がフィルタで飛ばされる重複辺の入力で破綻）。
   判定したい条件そのもの（子の有無／組の値の切り替わり）を、そのまま書けているかを確認する習慣が対策になる。
   2 件だけなので、思考の癖として確定するには今後の再発で判断する。

3. **別解・より良い方針** — 方針は妥当。ソートを使わない形もある: 同じ層の頂点を同値類ごとにランク順で並べて持ち、
   各同値類について数字 1〜9 の順に行き先を集めれば、それがそのまま次の層の同値類の順になる
   （隣接リストを数字ごとに分けておけば、層ごとのソートが不要で全体 O(N + M)）。

4. **実装の正しさ・計算量** — 修正後は問題なし。各頂点は1度だけ確定して prev に入るので、各辺を見るのは高々1回。
   ソートと map で全体 O(M log M)。細部:
   - `sort(all(nxts), compf)` の後に `coordinate_compression` が内部で再度ソートするので、ソートが二重（正しさには影響なし）。
   - `rep(i, n) sort(all(nexts[i]))` は、その後に nxts 全体をソートしているので不要。
   - 出力 2×10^5 行を `endl` で出しており、毎行フラッシュする。本問は通ったが、[[abc212_f]] で定数倍が問題になった記録があるので `'\n'` が安全。
